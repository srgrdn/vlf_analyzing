# Варианты обучения модели для детекции всплесков

Этот документ описывает варианты обучения модели, которая будет распознавать всплески на данных СДВ-приёмника и сравниваться с текущим пороговым детектором `detect_broadband_bursts.py`.

## Цель

Нужно получить модель, которая на тех же данных сможет находить короткие широкополосные всплески и дать честное сравнение с текущим алгоритмом:

- пороговый детектор строит огибающую мощности в заданной полосе частот;
- модель должна распознавать похожие события по сегментам, огибающей или спектрограмме;
- сравнение должно выполняться на одном и том же тестовом наборе.

## Вариант 1. Классификация сегментов по спектрограммам

Самый прямой вариант: режем запись на окна, например по `2 s`, строим спектрограмму в выбранной полосе, например `20-30 kHz`, и модель отвечает:

- `burst` — всплеск есть;
- `no_burst` — всплеска нет.

Подходящие модели:

- маленькая CNN с нуля;
- MobileNetV2 или EfficientNet через transfer learning;
- ResNet18 или ResNet50, если данных станет много.

Плюсы:

- проще всего собрать датасет;
- можно использовать текущие PNG или числовые матрицы спектрограмм;
- легко сравнивать с пороговым детектором.

Минусы:

- модель говорит, что всплеск есть в сегменте, но не обязательно точно указывает время внутри сегмента.

## Вариант 2. Детекция по временной огибающей

Берём не всю спектрограмму, а огибающую мощности в выбранной полосе частот. Это почти то же представление, которое уже использует `detect_broadband_bursts.py`.

Вход модели:

- 1D-массив `envelope_db`;
- временной шаг, например `0.002 s`;
- полоса частот, например `20-30 kHz`.

Подходящие модели:

- 1D CNN;
- MLP по признакам;
- LSTM/GRU, но не как первый вариант.

Признаки для простого MLP:

- максимум огибающей;
- медиана;
- MAD;
- отношение пика к фону;
- длительность превышения порога;
- площадь превышения порога.

Плюсы:

- быстро обучается;
- требует меньше данных;
- хорошо сравнивается с пороговым алгоритмом, потому что использует тот же источник признака.

Минусы:

- огибающая теряет частотно-временную структуру;
- если всплески отличаются именно по форме на спектрограмме, 1D-модель может проигрывать 2D-модели.

## Вариант 3. Предсказание координаты всплеска внутри сегмента

Сегмент подаётся на модель, а модель предсказывает:

- `has_burst`: есть всплеск или нет;
- `time_center`: положение всплеска внутри сегмента.

Например, для сегмента `2 s` модель может вернуть:

```text
has_burst = 1
time_center = 1.528
```

Плюсы:

- задача становится ближе к настоящей детекции;
- можно сравнивать не только факт наличия всплеска, но и ошибку по времени.

Минусы:

- нужна разметка времени события;
- начальную разметку можно получить пороговым детектором, но её всё равно желательно проверять руками.

## Вариант 4. Object detection на спектрограмме

Всплеск можно рассматривать как объект на изображении спектрограммы. Тогда размечаются прямоугольники вокруг вертикальных всплесков.

Подходящие модели:

- YOLO;
- RT-DETR;
- Faster R-CNN.

Плюсы:

- хорошо подходит для вертикальных событий на спектрограмме;
- модель сразу возвращает координаты события;
- удобно визуально проверять результат.

Минусы:

- нужна разметка bbox;
- больше инфраструктуры;
- тяжелее обучать и валидировать.

Этот вариант может быть сильным, если всплески хорошо видны как вертикальные структуры на спектрограмме.

## Вариант 5. Segmentation или heatmap

Модель предсказывает маску или тепловую карту вероятности всплеска на спектрограмме.

Плюсы:

- самая точная локализация;
- можно выделять форму события, а не только центр.

Минусы:

- самая дорогая разметка;
- больше сложность пайплайна;
- для первого этапа это, скорее всего, избыточно.

## Рекомендуемый старт

Практичный первый маршрут:

1. Обучить 1D CNN по огибающей.
2. Обучить 2D CNN по спектрограмме.
3. Сравнить обе модели с текущим пороговым детектором.

### 1D baseline по огибающей

Вход:

```text
envelope_db
```

Типичные параметры:

```text
freq_min = 20000
freq_max = 30000
time_resolution = 0.002
segment_duration = 2
```

Выход:

```text
burst / no_burst
```

Позже можно добавить:

```text
peak_time
```

### 2D baseline по спектрограмме

Вход:

```text
spec_db[frequency, time]
```

Типичные параметры:

```text
freq_min = 20000
freq_max = 30000
frequency_resolution = 50
time_resolution = 0.002
segment_duration = 2
```

Выход:

```text
burst / no_burst
```

## Как собрать датасет

Разметку можно ускорить текущим пороговым детектором:

1. Прогнать `detect_broadband_bursts.py` по всем сырым `.bin` файлам.
2. Сохранить по каждому сегменту:
   - спектрограмму;
   - огибающую;
   - CSV с временами срабатываний;
   - метку `burst` или `no_burst`.
3. Использовать пороговый детектор как черновую разметку.
4. Руками проверить спорные случаи:
   - слабые пики рядом с порогом;
   - одиночные вертикальные линии;
   - ложные срабатывания от устойчивых несущих;
   - сегменты без всплесков.

## Формат хранения датасета

Лучше хранить не только PNG, но и числовые данные в `.npz`.

Пример структуры:

```text
dataset/
  train/
    burst/
    no_burst/
  val/
    burst/
    no_burst/
  test/
    burst/
    no_burst/
  metadata.csv
```

Пример `metadata.csv`:

```csv
file,segment_start,segment_end,channel,freq_min,freq_max,label,peak_time,source
```

Для модели по огибающей:

```text
sample_id.npz
  envelope_db
  time_axis
  label
  peak_time
```

Для модели по спектрограмме:

```text
sample_id.npz
  spec_db
  time_axis
  freq_axis
  label
  peak_time
```

## Метрики сравнения

Для классификации сегментов:

- precision;
- recall;
- F1;
- confusion matrix.

Для детекции по времени:

- true positive, если пик найден в допустимом окне около разметки;
- false positive, если модель нашла всплеск там, где его нет;
- false negative, если модель пропустила размеченный всплеск.

Пример допуска по времени:

```text
detected_peak_time within +/- 20 ms from labeled_peak_time
```

Дополнительно полезно считать:

- количество ложных срабатываний в минуту;
- recall по сильным всплескам;
- recall по слабым всплескам;
- среднюю ошибку времени пика.

## Практический план работ

1. Доработать текущий детектор, чтобы он экспортировал обучающие примеры:
   - `spec_db`;
   - `envelope_db`;
   - `time_axis`;
   - `freq_axis`;
   - `label`;
   - `peak_time`.
2. Собрать небольшую ручную разметку, например `200-500` сегментов.
3. Обучить 1D CNN по огибающей.
4. Обучить 2D CNN по спектрограмме.
5. Сравнить обе модели с пороговым детектором на одном test-наборе.
6. Решить, нужна ли более сложная модель:
   - object detection;
   - heatmap;
   - segmentation.

## Вывод

Начинать лучше с двух baseline-подходов:

- 1D CNN по огибающей как прямой конкурент пороговому детектору;
- 2D CNN по спектрограмме как проверка, помогает ли частотно-временная структура.

Такой путь быстрее всего покажет, нужна ли нейросеть вообще, или хорошо настроенный адаптивный детектор уже решает задачу достаточно надёжно.
