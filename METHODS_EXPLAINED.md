# Методы распознавания всплесков

Документ описывает текущие методы распознавания всплесков в СДВ/VLF данных проекта.

Общий формат данных для обучения:

```text
raw_data/*.bin
  -> 2-секундные сегменты
  -> dataset/samples/*.npz
  -> dataset/review/burst/*.png
  -> dataset/review/no_burst/*.png
  -> dataset/metadata.csv
```

Один `.npz` соответствует одному 2-секундному сегменту и содержит:

```text
spec_db       спектрограмма, матрица частота x время
envelope_db   огибающая мощности в выбранной полосе
time_axis     временная ось
freq_axis     частотная ось
label         метка, если она есть
```

PNG-файлы нужны человеку для просмотра и ручной разметки. Модели обучаются не по PNG, а по массивам из `.npz`.

## Метод 1: 1D CNN по огибающей

Папка:

```text
methods/1d_cnn_envelope/
```

Ноутбук:

```text
methods/1d_cnn_envelope/train_envelope_1d_cnn.ipynb
```

Скрипт:

```text
methods/1d_cnn_envelope/train_envelope_1d_cnn.py
```

### Идея

В этом методе модель смотрит только на `envelope_db`: одномерную временную огибающую мощности в выбранной полосе частот, например `20000-30000 Hz`.

То есть исходная спектрограмма сначала сворачивается по частоте:

```text
spec_db[freq, time] -> envelope_db[time]
```

Если во всём частотном диапазоне появляется короткий широкополосный всплеск, энергия в полосе растёт, и на огибающей появляется пик.

### Что видит модель

Модель видит:

```text
амплитуда/мощность в полосе -> как она меняется во времени
```

Модель хорошо замечает:

```text
короткие пики мощности
резкие выбросы
общую динамику энергии в полосе
```

Модель не видит напрямую:

```text
на какой именно частоте произошло событие
форму события по частоте
вертикальную структуру на спектрограмме
узкие частотные линии
```

### Архитектура

Используется простая 1D CNN:

```text
Conv1d -> BatchNorm -> ReLU -> MaxPool
Conv1d -> BatchNorm -> ReLU -> MaxPool
Conv1d -> BatchNorm -> ReLU
AdaptiveAvgPool1d
Linear -> 2 класса
```

Классы:

```text
no_burst
burst
```

### Плюсы

Метод быстрый на CPU.

Он использует компактный вход: примерно `991` точка на 2 секунды при текущем разрешении `0.002 s`.

Он хорошо подходит как первый baseline, потому что всплеск часто проявляется именно как пик энергии.

Он менее склонен переобучаться на детали картинки, потому что не видит лишние структуры спектрограммы.

### Минусы

Метод теряет частотную информацию.

Если всплеск слабый, узкий, или похож на изменение фоновой линии, огибающая может быть недостаточно выразительной.

Если в полосе есть постоянные мощные несущие или шумовые изменения, они могут давать ложные срабатывания.

### Текущий результат

Первый прогон дал примерно:

```text
TEST accuracy  около 0.87
TEST F1        около 0.87
burst recall   около 0.93
burst precision около 0.83
```

Это хороший стартовый результат для небольшого датасета и CPU-обучения.

### Когда использовать

Этот метод стоит считать основным baseline на текущем этапе.

Его удобно использовать для:

```text
быстрой проверки качества разметки
поиска подозрительных ошибок в датасете
первого рабочего классификатора
сравнения с пороговым детектором
```

## Метод 2: 2D CNN по спектрограмме

Папка:

```text
methods/2d_cnn_spectrogram/
```

Ноутбук:

```text
methods/2d_cnn_spectrogram/train_spectrogram_2d_cnn.ipynb
```

Скрипт:

```text
methods/2d_cnn_spectrogram/train_spectrogram_2d_cnn.py
```

### Идея

В этом методе модель смотрит на всю спектрограмму `spec_db` как на двумерную матрицу:

```text
частота x время
```

Для текущих параметров один сегмент имеет форму примерно:

```text
201 частотный бин x 991 временной бин
```

В отличие от 1D CNN, модель видит не только рост энергии во времени, но и то, как событие выглядит по частоте.

### Что видит модель

Модель видит:

```text
вертикальные всплески
частотные линии
ширину события по частоте
форму события по времени и частоте
фоновые структуры спектра
```

Это важно, потому что на спектрограмме всплеск часто выглядит как вертикальная структура, проходящая через диапазон частот.

### Архитектура

Используется простая 2D CNN:

```text
Conv2d -> BatchNorm -> ReLU -> MaxPool
Conv2d -> BatchNorm -> ReLU -> MaxPool
Conv2d -> BatchNorm -> ReLU
AdaptiveAvgPool2d
Linear -> 2 класса
```

Классы:

```text
no_burst
burst
```

### Плюсы

Метод использует больше информации, чем 1D CNN.

Он потенциально может отличать настоящий широкополосный всплеск от простого роста энергии в полосе.

Он может учитывать геометрию события на спектрограмме.

### Минусы

Метод значительно медленнее на CPU.

Он требует больше данных, потому что вход намного богаче и модель легче переобучается.

На маленьком датасете модель может начать учить случайные особенности: фоновые линии, шум, особенности отдельных файлов.

Текущий простой вариант 2D CNN обучается нестабильно: на отдельных эпохах `val_f1` резко проваливался.

### Текущий результат

Первый прогон дал примерно:

```text
TEST accuracy  около 0.81
TEST F1        около 0.80
burst recall   около 0.89
burst precision около 0.76
```

Сейчас этот результат хуже, чем у 1D CNN.

Это не означает, что 2D-подход плохой. Скорее текущей 2D-модели мало данных или нужна более спокойная настройка обучения.

### Что стоит попробовать дальше

Для второго прогона 2D CNN можно уменьшить скорость обучения:

```python
LEARNING_RATE = 3e-4
EPOCHS = 40
BATCH_SIZE = 16
```

Также можно усилить регуляризацию:

```text
увеличить Dropout
добавить early stopping
сделать архитектуру чуть меньше
проверить ошибки модели глазами
```

### Когда использовать

2D CNN стоит развивать, если нужно распознавать именно форму события на спектрограмме.

Этот метод особенно полезен, если:

```text
1D CNN путает всплески с обычными энергетическими выбросами
важна частотная структура
в будущем появится больше размеченных данных
нужно сравнить модель с визуальной логикой человека
```

## Метод 3: Threshold pseudo-labeling

Папка:

```text
methods/threshold_pseudo_labeling/
```

Подготовка датасета:

```text
methods/threshold_pseudo_labeling/prepare_threshold_dataset.py
```

Ноутбук:

```text
methods/threshold_pseudo_labeling/train_threshold_pseudo_labeling.ipynb
```

Скрипт обучения:

```text
methods/threshold_pseudo_labeling/train_pseudo_envelope_1d_cnn.py
```

### Идея

Этот метод использует существующий пороговый детектор как автоматического разметчика.

Логика:

```text
detect_broadband_bursts.py нашёл пик в сегменте -> label = burst
detect_broadband_bursts.py не нашёл пик -> label = no_burst
```

Такие метки называются:

```text
pseudo-labels
weak labels
слабая автоматическая разметка
```

После этого нейросеть обучается не на ручной разметке, а на разметке, которую сгенерировал пороговый детектор.

### Зачем это нужно

Ручная разметка дорогая: человек должен открыть много спектрограмм и принять решение.

Пороговый детектор может быстро разметить тысячи сегментов.

Даже если он ошибается, его разметка полезна как черновой датасет.

Нейросеть может научиться приближать поведение детектора, а затем использоваться для поиска расхождений:

```text
детектор говорит burst, модель говорит no_burst
детектор говорит no_burst, модель говорит burst
```

Такие расхождения наиболее интересны для ручной проверки.

### Структура датасета метода

Третий метод хранит свой датасет отдельно:

```text
methods/threshold_pseudo_labeling/dataset/
  samples/
  review/
    burst/
    no_burst/
  verify/
    burst/
    no_burst/
  metadata.csv
```

`review/burst` и `review/no_burst` заполняются автоматически по решению детектора.

`verify/burst` и `verify/no_burst` предназначены для ручной независимой проверки.

### Команда подготовки

Запуск из корня проекта:

```powershell
python .\methods\threshold_pseudo_labeling\prepare_threshold_dataset.py .\raw_data --channel ns --freq-min 20000 --freq-max 30000 --time-resolution 0.002 --frequency-resolution 50 --segment-duration 2 --threshold-mad 8 --overwrite
```

Параметры соответствуют текущему рабочему режиму:

```text
channel ns
band 20000-30000 Hz
segment 2 s
time step 0.002 s
frequency step 50 Hz
threshold MAD 8
```

### Что делает подготовщик

Для каждого `.bin` файла:

```text
читает канал ns
режет запись на 2-секундные сегменты
строит спектрограмму
считает мощность в полосе
строит envelope_db
считает robust threshold = median + K * MAD_sigma
ищет пики выше порога
ставит pseudo-label
сохраняет .npz
сохраняет PNG в review/burst или review/no_burst
записывает metadata.csv
```

### Что обучается

Сейчас в третьем методе обучается 1D CNN по `envelope_db`.

Это сделано намеренно: разметка пришла от порогового детектора, который тоже работает по огибающей мощности в полосе. Поэтому первая модель должна научиться именно этой логике.

### Плюсы

Метод позволяет быстро получить большой обучающий набор.

Он хорошо подходит для масштабирования разметки.

Он помогает искать спорные случаи и расхождения между детектором и моделью.

Он может быть полезен как предварительное обучение перед дообучением на ручной разметке.

### Минусы

Модель наследует ошибки детектора.

Если детектор систематически пропускает слабые всплески, модель тоже может научиться их пропускать.

Если детектор часто срабатывает на помехи, модель может считать такие помехи всплесками.

Этот метод не заменяет ручную проверку. Он помогает уменьшить объём ручной работы.

### Как использовать правильно

Лучший сценарий:

```text
1. Детектор автоматически размечает большой набор.
2. Модель обучается на pseudo-labels.
3. Модель прогоняется по данным.
4. Сегменты, где модель и детектор не согласны, отправляются человеку.
5. Человек исправляет самые полезные ошибки.
6. Чистая ручная разметка используется для финального обучения или валидации.
```

## Сравнение методов

| Метод | Вход | Скорость CPU | Что видит | Текущий статус |
|---|---|---:|---|---|
| 1D CNN envelope | `envelope_db` | высокая | мощность во времени | лучший baseline сейчас |
| 2D CNN spectrogram | `spec_db` | ниже | время + частота | перспективно, но пока нестабильно |
| Threshold pseudo-labeling | `envelope_db` + labels от детектора | высокая после подготовки | поведение детектора | нужен для масштабирования |

## Что считать основной метрикой

Для задачи всплесков важны:

```text
burst recall
burst precision
F1 по классу burst
confusion matrix
```

`burst recall` показывает, сколько настоящих всплесков модель нашла.

`burst precision` показывает, сколько найденных моделью всплесков действительно являются всплесками.

Если цель не пропускать события, важнее `recall`.

Если цель не завалить оператора ложными срабатываниями, важнее `precision`.

На текущем этапе нужно смотреть оба значения.

## Рекомендуемый дальнейший план

1. Продолжить чистку ручной разметки через ошибки `1D CNN`.
2. Переобучить `1D CNN` после исправления явных ошибок.
3. Запустить второй прогон `2D CNN` с меньшим `LEARNING_RATE = 3e-4`.
4. Подготовить pseudo-label dataset третьим методом.
5. Сравнить detector, 1D CNN, 2D CNN и pseudo-label model на одном verify-наборе.
6. Завести отдельный список спорных примеров, если их станет много.

## Главный вывод

На текущем размере датасета самый практичный метод - `1D CNN по envelope_db`.

`2D CNN` потенциально богаче, но ей нужно больше данных или более аккуратное обучение.

`Threshold pseudo-labeling` нужен не как финальная лучшая модель, а как способ быстро расширять датасет и находить интересные случаи для ручной проверки.
